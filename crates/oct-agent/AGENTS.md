# oct-agent AGENTS.md

后端服务 crate。用户侧概览见 `README.md`；数据库/构建/迁移的全局约定见仓库根 `AGENTS.md`。

## Architecture

- **Interactive terminals** (`terminal.rs` + `terminal/pty_io.rs` + `api/terminals.rs`): `AppState.terminals` 持有项目级 portable-pty 会话；与 agent 执行工具/审批独立，当前只接受人工输入。REST 生命周期 + 单控制者 WebSocket，二进制输出前 8 字节为大端字节偏移，JSON 控制帧 ready/live/exit/error；客户端渲染并发送查询回复后用 ack 确认字节位置，ready.replay_reply_after 区分旧查询与未处理查询；最近约 1 MiB 重放，断线不杀 shell，关闭/删项目才清理，后端重启不恢复。PTY IO 与进程回收用独立线程；Unix IO 非阻塞、有限 poll 等待可取消，关闭等待三个 worker 退出并释放全部 master 句柄（后台进程保留 slave 也不阻塞）。进程 kill 与 reap 由同一 worker 持有，避免过期 PID。Origin 校验要求代理保留 Host（Vite 开 `ws: true`）。
- **Agent loop** (`agent/`): `loop_runner.rs` 只协调阶段和 run 级结果；`loop_runner/maintenance.rs` 持跨回合的 microcompact/summary 开关与 projection 装配，`model_turn.rs` 收集单次模型流并保存 assistant（保存后将消息移入 context），`tool_batch.rs` 独占工具批次的 `JoinSet` 和结算。工具调用 drop/cancel 中止未完成调用，兄弟工具继续执行、完成即落库（避免 SQLite 事务死锁）；结果持久化先于 ToolResult 事件，取消先 shutdown 工具再补未完成结果。取消走 `CancellationToken`，无迭代上限；返回类型化 `RunOutcome`——终态/最终消息/部分输出不靠监听 SSE 拼出。
- **Conversation application** (`application/conversation/`): `ConversationApplication` 提供 send/resume/compact/wake、指令 reload 与恢复资格查询；内部 command/outcome 不依赖 axum 或 API DTO。应用层拥有版本/模型/reasoning 校验、历史准备、附件提交、title 触发、恢复编排与 wake 准备，直接调用 `application/execution.rs` 的公共 launcher。HTTP 只转换请求/响应；通知调度在 `application/notifications.rs`，启动入口持有 `WakeDrainer` 的关闭句柄；后台 manager 只发会话级信号。准备/恢复模块仅在应用层 crate 内可见，旧 runtime/subagent 兼容出口已移除。
- **Run lifecycle** (`runtime/` + `application/execution.rs`): `application/services.rs` 的 `ApplicationServices` 只持共享资源和装配/占用构造能力，字段限 crate 内访问；composition root 通过 `ServiceResources` 注入，`AppState` 仅保存应用命令和共享查询组件。旧 `RunService` 转发层已移除；根/子装配分别在 `application/assembly/root.rs`、`worker.rs`，共享资源/权限和冻结 prompt 在同目录。发送准备、注册→装配→监督交接由独立 Tokio 任务持有，丢弃等待者不丢执行所有者，取消经原 token 到达启动阶段。`runtime/execution.rs` 接收组装好的 context，统一监督与持久化终态，不依赖应用服务或完整子代理 manager；子完成 observer 仅持活动索引/父事件出口/done sender。终态落库和通知先于占用释放/SSE EOF。启动 `bootstrap` 将遗留 running 标 lost。`ModelResolver` 仅持 pool/ProviderRegistry，标题任务经 `application/title.rs` 独立准备；会话/项目删除的跨服务 drain、制品清理与 sweep 归 `application/lifecycle.rs`，`runtime/lifecycle.rs` 只保留 admission/tombstone；活动权限门操作归 `application/permissions.rs`。
- **Subagent** (`application/delegation.rs` + `subagent/`): `task` 工具委派独立子会话（`kind='subagent'`，普通 send/resume/compact 409 `managed_conversation`）；同 `(parent_run_id, parent_tool_call_id)` 注册幂等。注册→装配→监督接管由独立 Tokio 任务持有，父工具 future 被 drop 不会中止它，父取消通过 token 通知；注册后立即占用子会话，装配失败/取消/panic 均先落终态再释放占用。父装配在添加 task 前捕获 `WorkerInheritance`（冻结工具描述 + 可复用 MCP Arc，不保留原生工具或 task/task_stop）；子工具集按封存快照选择，文件/搜索/命令工具按子会话作用域、共享 `WorkspaceFileLocks` + 每 run 独立 `AgentReadState` 重建，MCP schema 与派发精确等价；子取消 token 是父的 `child_token()`。审批向父/子 hub 双向发布，decide 任一侧可路由、同一决定只生效一次；allow_always 注入整棵活动树。恢复：终态直接回填（不重跑子模型）、`lost` 或无执行所有者的 `running` 同 run 行续跑（epoch+1，迟到实例写入被守卫拒绝）；取消接口覆盖启动期 token 及无执行所有者的 `running`/`lost` 行（注册锁+会话占用保护），无需重启。存在未结算委派时 send/compact 409 `pending_recovery`。父子 loop 并发写库靠 `insert_message` 的 SQLITE_BUSY(5/517) 重试。
- **History boundary** (`history/` + `application/history.rs` + `db/history.rs` + `api/history.rs`): 中性 `HistorySnapshot`/`HistoryPlan` 与纯 cut/tool-batch/COW/draft 规则不依赖 sqlx 行、AppError 或 HTTP；共享内容解析在 `history/content.rs`，StoredMessage 也复用它（保留 v1/v2 附件语义）。应用层拥有 UUID/revision/title 校验、lifecycle admission、源占用与活动任务检查；已完成 operation 收据仍先于占用重放。仓储持有完整 BEGIN IMMEDIATE：检查收据/revision/pending → 读 membership + 按纯切点规则一次批量加载需恢复的 COW 原文（head 不加载） → 纯计划 → membership/全量备份/revision/收据提交；不能在应用层 plan 后另开事务 apply。HTTP 的 Fork/Revert DTO 与内部收据类型分离，JSON 形状保持；request/cut 统一从 `history` 引用，旧 `db::history` 类型兼容出口已移除。
- **Agent 配置**（`agent_settings/` + `application/settings.rs` + `db/agent_settings.rs` + `api/agent_settings.rs`）: 中性类型/纯策略拥有内置 `worker`/`title` 全局→项目逐字段覆盖、形状/引用事实校验与 WorkerSnapshot 兼容规则，不依赖 SQL、AppError 或 HTTP。HTTP DTO 将 PATCH 遗漏/null/值转换为 `Keep/Inherit/Set`，展示名称/描述也留在 API。应用更新持有完整 BEGIN IMMEDIATE：读取 global/local 与有效工具模式→patch/合并→形状/引用校验→仓储写入；`db/settings.rs` 的工具模式读取支持同一事务连接，运行准备复用它。编辑读取允许失效模型/MCP 引用以便修复，运行读取拒绝失效引用。`application/delegation.rs` 在新 run 注册事务中将指令/工具身份封存进 `agent_runs.agent_config_json`；`runtime/worker_config.rs` 负责候选选择和按封存身份重建工具，恢复只用原快照（NULL 兼容旧行）；中性工具模式枚举的 serde 默认始终为 direct，运行时未配置的默认仍为 code。
- **Repo instructions & 冻结 prompt 环境**（`agent/repo_instructions.rs` + `application/assembly/prompt_env.rs`）: 发现链=working_dir 沿祖先链到 git root 逐目录取 `AGENTS.md` → `CLAUDE.md` **首个命中**（每目录最多一个）；预算 32 KiB/文件、64 KiB 总量。块 + MCP 工具身份按根会话**冻结**（`application::assembly` 的共享 prompt cache）保 provider prefix cache——只在首次装配、压缩/microcompact 之后、`POST /api/conversations/{id}/instructions/reload` 三个显式点刷新，run 中途恒定；子代理共享整棵树同一条目。故意不冻结：code mode 切换、附加目录、worker 指令。
- **Background bash** (`runtime/background.rs` + `application/notifications.rs`): `run_in_background` **envelope 即答**；子进程输出 fd 直写 `{db目录}/exec/{conv}/{task_id}.log`（按会话额外开放 `exec/{conv}` 的读取，子代理继承根会话；其他会话/全局 exec 目录仍按项目工作目录及附加目录分类，工作区内默认可读，工作区外遵循权限规则和模式——default/accept_edits 默认需要审批。整个 exec 目录在任何权限模式下 write/edit 均拒绝；模型用通用 read/grep/glob 读取）。终态→等会话空闲→单事务插 `<task-notification>` user 消息 + 以会话上次 provider/model 起 wake run（不触发 title）；send/resume 入口 catch-up 补投。进程 manager 不持应用服务，也不聚合通知；终态落库后通过 channel 发会话级信号，应用 drainer 启动扫描/重试从 DB 取待办，关闭时取消并 join 所有等待 worker。**不随 run 死**——只有 task_stop/HTTP cancel/会话删除两阶段杀（SIGTERM→1.5s→SIGKILL）；watchdog 1GiB 输出/24h 运行上限。
- **Tool boundary** (`tool_contract/` + `tool_host/` + `events/`): `AgentTool`/`ToolSelector`/`ToolCallIdentity`/`ToolOutput` 与平滑后的输出能力不依赖 agent、事件 hub、DB 或应用服务；`ToolContext` 只提供调用身份、取消和 typed progress sink，无 `hub()`。普通/嵌套调用共用宿主 dispatch 与权限门；code mode 独立注入审批 hub 和 typed nested observer，trace flush 仍先于 NestedToolUpdate。`AgentEvent`/`EventHub` 统一从 `events` 引用，工具契约统一从 `tool_contract` 引用；`ToolSelector`、`McpToolMode` 与 `CODE_CATALOG_VERSION` 位于 `tool_contract/identity.rs`；旧 agent/tools/settings/code-mode 类型兼容导出已移除，事件/schema 名称与 JSON 字段不变。
- **Agent tools** (`tools/`): `read`/`write`/`edit_file`/`listdir`/`grep`/`glob`/`execute`（含 `run_in_background`）/`task_stop`/`task`（后两者仅 root toolset）。后台与委派工具只持按 run 绑定的 `BackgroundCommands`/`TaskDelegation`，不读 DB、不持全局 manager；归属校验与 running/lost/终态处理在应用适配器内完成。状态拆分：共享 `WorkspaceFileLocks`（跨 agent 串行）+ 每 run `AgentReadState`（阅读记录互不授权）；多根工作区沙箱解析在 `workspace`。
- **Code mode** (`src/codemode/` + `application/assembly/code_recovery.rs`): `mcp_tool_mode=code` 时 MCP 工具收进单一 `execute_code`——每 run 发布只读 SDK（`{db目录}/codemode/{conv}/{run}/sdk/`，模型用普通 read/grep/glob 浏览，`.js` 虚拟模块由 worker 提供）；宿主调用复用普通审批/文件锁/阅读状态；JS 无直接文件/网络/进程，仅 `text()`/`console.log()`/`image()` 显式输出进上下文。崩溃恢复从上个 run 的有界 trace 恢复嵌套调用状态（不重跑历史脚本）。代码模式下 worker 非空 allowlist 必含 read/grep/glob。限额/协议/完整规范见 `crates/oct-codemode/README.md`。
- **Permissions** (`src/permissions/`): 每次 model 驱动的工具调用过 `PermissionGate`——`permission_rules` + 会话 `permission_mode` 按固定优先级 **deny > ask > allow > mode 默认** 裁决（tool 精确名或 `mcp__{server}__*` 通配；pattern 为 NULL/命令前缀/绝对路径 glob）。Ask 停进内存 registry（oneshot、fail-closed 超时）；allow_always 带 pattern 落 source=`approval` 的持久规则；审批本身内存态不落库。后台任务输出目录内建 deny。
- **Microcompact** (`agent/micro.rs`): 摘要压缩前的廉价第一级——turn-top 把旧的成功态工具结果 **COW 替换**为占位符（副本 `supersedes_message_id` 回指原文恒一跳，绝不改原文）。触发：水位 ≥ 窗口×70%（compact 是 85%）或 run 启动时会话已空闲 ≥ 60min。永不清错误结果/最后一轮/已是占位符的行。`GET /api/conversations/{id}/messages/{copy_id}/original` 沿 supersedes 一跳取原文。
- **Context state** (`context.rs`): DB 与 agent 共享的中性层——token 估算（`estimate_*`）、`LlmView`/`UsageAnchor`、loop 运行态 `ContextState`（`append`/`apply_compaction`/`apply_clears` 是唯一变换入口，与重新 `load_llm_view` 保持一致）。
  图片轻引用与 data URL 共用 1200 token/张的启发式预算；`context/projection.rs` 纯函数先做模态门控/媒体预算，`attachments/request.rs::RequestAssembler` 再物化选中的字节；turn-top 先确认缺失文件的最终投影再校验锚点/判断压缩，维护未改历史时直接复用已物化请求。估算、请求和 assistant details 的 `projection` 快照共用同一投影；快照记录 system/逐 ordering 的指纹与估算（含归一化版本、预算省略、文件缺失结果）。后续请求比较已测前缀，追加消息仍有效；投影改变或旧行缺快照则失效锚点。COW 在内存与 DB 重载均按已测投影扣减，未发出的图片不能重复扣 token。
- **Context compaction** (`agent/compact.rs` + `db/messages.rs::load_llm_view`): 触发=turn 顶部「真实 usage 锚点+本地估算」≥ 窗口×0.85 或手动 `/compact`；手动/自动共用 `run_compaction`。关键不变式：标记行**插在切点槽位**（region 与 tail 之间——追加末尾会让 tail 落到 marker 之前、下个 run 从视图消失）；**老行永不删除**，视图=最新 marker 之后（孤儿 ToolResult 过滤）；anchor 须晚于 marker；尾部 verbatim 保留（窗口/10 封顶 32k，不拆 tool_call/result 对）；摘要失败只禁用自动、再触发需 est ≥ 压缩后估算 + tail 预算（防死循环）。
- **Attachments** (`attachment_types.rs` + `attachments/` + `db/attachments.rs` + `api/attachments.rs`): `UserContent {body, attachments}` 明确区分人类正文与资产；文本附件的 `TextSnapshot` 在 send 时按窗口 10%（封顶 32k、未知窗口 16k、单文件 256KiB）冻结进 details，parts 仅存正文/轻量标签/资源引用，public DTO 只给正文和附件链接。旧格式仅在兼容读取器按旧布局解析，不重写不可变内容行。`AttachmentService` 封装上传/草稿票据/prepare+commit/工具媒体/GC 的锁与事务；`AssetStore` 只管私有目录 0700、文件 0600 和相对 storage key，不知道 DB/消息。composition root 将同一 `AttachmentService` 实例注入应用资源与 `AppState.attachments`，上传/读取/发送/回收共用它。上传网络 IO 仅 pin 路径；本地发布/发送准备到原子认领+消息+ownership index 提交持私有共享 lease，GC 独占，文件 IO 不持 SQLite 写事务。用户和工具图片共用 `MediaNormalizer`：完整解码、40M 像素上限、并发 2、模型衍生图最长边 2000/至多 3MiB，重编码前应用 EXIF 朝向（normalizer v2），原图不变，GIF 取首帧；拒绝坏图/不支持的媒体。请求先门控，再用元数据执行总媒体预算（40MiB 编码字节/64 张，应用默认值），最后才读入/base64；保留当前 user 和最近工具轮，旧图按从旧到新省略，受保护内容超限显式失败。缺文件替换注记并改变投影快照。文本提示使用 `oct-attachment://{asset_id}`，文件工具经 service 的逻辑资源表映射到当前只读根，仍走原权限门，搬目录不改变冻结文本。`sweep` 用 `message_assets` 索引及未过期 staged ticket 决定存活，不扫描 JSON；fork 共享内容行、COW 原文/回退备份保留 ownership，删除最后引用才回收，staged 24h 到期。草稿 copy 只签发新 ticket 复用同一 asset，不复制字节。迁移回填旧 ownership；出现 v2 内容后禁止有损降级。
- **MCP support** (`src/mcp/` + `api/mcp.rs` + `oauth.rs`; 底层 crate 见 `crates/oct-mcp`): `McpManager` 每 chat turn 按项目对账 enabled `mcp_servers` 行（作用域两级合并）。并发模型：决策在短 `decide_lock` 内无网络等待完成，连接/移除各持该 server 的 gate；OAuth `invalidate` 推进失效 epoch 而非等在途握手（迟到结果不回写）。`tools/list_changed` 500ms 去抖重 list（`ManagedServer.generation` 防旧监听写新 entry）。工具超时默认 60s（行级覆盖），取消经 cancel_token select 中断在飞调用（不 shutdown 共享连接）。图片多模态：anthropic tool_result 变块数组，openai 兼容侧追加 user 消息带 data URL。OAuth=授权码+PKCE S256+RFC 8414/7591，token/secret 不进日志与 OpenAPI。

- **Git Changes** (`application/git.rs` + `git/` + `api/git.rs`): 应用层从项目解析工作目录，`Repository` 验证其为仓库根并按 canonical root 共享 status/diff/action 锁；`queries.rs` 负责查询与 diff，`actions.rs` 校验选择并执行操作，`process.rs` 集中无 shell argv、literal pathspec、超时/输出限额与 kill-on-drop，`parse.rs` 解析 NUL 分隔输出。内部命令/快照不依赖 HTTP DTO；API 只做 DTO/OpenAPI 和错误协议转换。沿用 Git 集成测试中的本地临时仓库及本地 remote，不访问外部 Git 服务。

附件的会话额外读取授权按会话内已发送的 `UserContent` 附件和工具图片逐文件建立（含 fork 共享消息、COW 原文；子代理继承根会话）。资源映射仅在运行存活期间共享，工具图片提交后更新；未发送草稿、任意正文中的 URI、其他会话资产均不产生会话额外授权，资产父目录也不因此获得额外授权。会话额外授权与项目工作目录及附加目录的读取范围取并集，仍受显式权限规则裁决：其他会话资产或草稿的文件路径位于工作区内时默认可读，位于工作区外时按权限规则和模式处理（default/accept_edits 默认 Ask，bypass 默认 Allow）；运行时数据目录位于工作区内时也遵循这一规则。`oct-attachment://` 只按会话资源映射解析，工作区范围不会扩大 URI 的解析范围。`message_assets` 是 GC 索引，不能单独当授权依据；整个附件存储根仍受 write/edit 内建 deny 保护。

HTTP 不可从 AppState 取得完整应用资源、RootRunRequest 或 assembler。入口与资源装配分别由 `AppState::new` 和 `ApplicationServices::new(ServiceResources)` 构造；集成测试保留自己显式注入的资源 clone 以协调 prompt 锁、活动索引和占用，不通过 HTTP state 取回完整运行服务。

## API

路由全表以 `api/mod.rs` 的 `api_routes` 与 `/scalar`（OpenAPI）为准，只列**非显然语义**：

- Send 带 `expected_revision`（history 准备前校验）与可选 `attachment_ids`（staged 附件认领）；`POST …/attachments`（multipart 上传，路由级 body limit）与 `GET /attachments/{id}`（图片按类型读取，文本统一 text/plain + nosniff，immutable 缓存头）；`POST …/{id}/resume` 兼作子代理崩溃恢复入口（orchestrator 先重建任务树再续父 loop）；`GET …/{id}/run` + `GET …/{id}/events` 供前端刷新后接回在飞 run。
- **Fork**：切点=head / before-user / after-assistant / 闭合 tool 批之后（并行批不可拆）；共享内容行、复制 membership，**绝不**复制 runs/tasks/read grants；请求带 `operation_id`+`expected_revision`；切点丢弃其后的 marker、恢复其后被 COW 换掉的原文；before-user 的 `draft` 仅含用户正文，`draft_attachments` 保留图片/文本元数据，前端经 `POST …/attachments/{attachment_id}/copy` 签发目标会话的新 staged 票据（共享资产）后才可重发（revert 同源）；以 tool 结果结尾的 fork 可无 run 恢复且不得重放历史工具。
- **Revert**：整段 pre-revert membership 存为只读备份（origin_kind='revert_backup'），单事务替换原时间线；context_revision/history_epoch 递增；活动受管任务/未通知后台任务/未完成 wake 阻塞 revert；备份会话拒绝 send/resume/compact/revert/权限变更（rename/delete/fork 可用）。
- 根/子 `GET /messages` 共用事务快照，带 `X-Context-Revision`、`X-History-Epoch` 与 `X-Context-Tokens`；DTO 的 `appended_at_revision` 是不可变 membership 插入版本。
- `runtime/replay.rs` 在准备写入完成后冻结持久化边界，在内容事件之前向该 execution 的 hub 发布一次 `run_meta {run_id, execution_epoch, history_epoch, replay_after_revision, trigger_message_id}`。原 send/resume 订阅和 GET events 重连共享同一条控制记录；恢复期间允许子任务状态早于 ready，但不能让内容事件早于 ready。trigger 只标识 UI 轮次，不是重放边界；ordering 会被 marker 重排，不能代替 membership revision。

## Database Schema

列级定义以 `migrations/`（按时间序累加）与 `.sqlx/` 为准，只列**不变式**：

- `messages` 是**纯内容行、insert-only**（唯一后续写=usage 回填），跨 fork 共享；`conversation_messages` 是会话时间线：ordering 每会话唯一，`appended_at_revision` 插入时盖章永不变（fork/revert 切点与 anchor 资格判定用时点），`swapped_at_revision` 标记 COW 换指针。fork=复制行共享内容行，回滚=截断，microcompact COW=拨 message_id 指针（`apply_cow_swaps`）。
- fork/revert 元数据（`forked_from_conversation_id` 等、`conversation_fork_operations`/`conversation_revert_operations` 幂等收据）**不复用** subagent 的 parent/root 字段；`origin_kind`/`history_epoch` 区分世代（root latest/recovery 仅查当前世代）。
- `agent_runs` 根/子共用：`(parent_run_id, parent_tool_call_id)` 幂等键；`execution_epoch` crash 续跑递增、迟到实例写入被守卫拒绝；`agent_config_json` 封存 worker 快照；status `lost`=可恢复中断。
- `attachment_assets` 是不可变原始字节/模型衍生字节元数据；`staged_uploads` 是一次发送票据（staged|sent、asset_id，conversation_id 仅来源无 FK）；`message_assets` 把资产绑定不可变内容行（message FK cascade、asset FK restrict），与消息同事务写。内容行跨 fork 共享，sent 票据不是 GC 根。
- `settings`/`project_settings` 是 KV：已知键由对应类型/应用用例解释（`llm_wire_log`、全局/项目 `mcp_tool_mode`、`agent.{key}`），HTTP DTO 单独转换。

## Testing

- CI 铁律：测试绝不调用真实模型，全部由本地 mock 驱动。
- `tests/support/` 基建（各集成测试文件共用）：`TestApp` 在随机端口起真实 axum 服务器 + 临时文件 SQLite（**不要 `:memory:`**——连接池各连接是独立的库）；LLM 是 `llm.rs` 的 OpenAI 兼容 mock（经 `POST /api/providers` 的 base_url 注入），`push_marker_turns` 按请求内容 marker 做多 agent 剧本路由（并行 tool call 需 `tool_call_chunk_at` 传不同 index）；另有 `anthropic_llm.rs`、`mcp.rs`（`FakeMcpConnection`，不起真 server）、`oauth_as.rs`（本地授权服务器）。
- 崩溃模拟统一手法：WAL checkpoint + db 文件复制 + `TestApp::new_with_dir`。
- 禁 sleep 等并发：取消用 `CancellationToken`，等事件用 `rx.recv()` + timeout 兜底，SSE 断言以流 EOF 为终止信号。
- 测试文件按主题拆分（`agent_loop`/`api_e2e`/`attachments`/`subagent_runtime`/`background_tasks`/`code_mode`/`conversation_fork`/`conversation_revert`/`git_api`/`mcp_oauth`/`agent_settings`/`tool_transactions`/`notification_history`/`*_recovery_*` 等）；`code_mode.rs` 起 true V8 helper 的用例在 `--features code-mode-tests` 之后（见 `crates/oct-codemode/AGENTS.md` 的 preserve_order 陷阱）。工具层为内联 `#[cfg(test)]` 测试。

工具能力/所有权回归见 `tests/application_capabilities.rs`（无信号启动扫描、busy waiter 关闭与应用释放）；`application/inheritance.rs` 单测确认原生/root 控制实例不被继承、MCP 派发仍为同一 Arc。`TestApp` 默认启动真实应用 drainer；隔离 send catch-up 的测试可显式使用 `new_with_dir_without_wake_drainer`。

history 纯规则测试见 `history/tests.rs`（并行工具批、marker 的 revision、COW 一跳、附件草稿与旧 request 收据）；直接应用命令测试见 `tests/application_history.rs`（revert 成功收据在源已占用时重放、相同 operation 的冲突与新操作的 busy 拒绝）。既有 fork/revert 集成测试继续覆盖事务回滚、恢复、备份和附件归属。
